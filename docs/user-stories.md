## 1. 本次调整与设计口径

### 已确定的调整

| 事项 | v0.4 口径 |
| --- | --- |
| 网站首页 | 直接进入平台推荐的无限发现页，连续浏览推荐任务 |
| 看板与排行榜 | 合并在同一页面，提供整体差距看板与按热度排序的任务排行榜 |
| 生成者与投票者 | 由平台在云端运行，承担作品生成、偏好学习、验证和对抗 |
| 云端控制权 | 仅平台管理员通过管理员 Dashboard（官方后台）启动、取消、重跑、调整配置与预算；普通用户无控制权限 |
| 新任务发布 | 必须提供至少一件人类作品和一件 agent 作品，连同任务信息通过审核后公开 |
| 追加参选 | 所有用户都可在网站向任何公开可见任务单独追加人类或 agent 作品，无需任务作者邀请或批准；任务可见即已过审，不因追加而重新送审 |
| 上传范围 | 支持常见文件格式、压缩包、链接和直接输入的文本；学习授权属于作品上传表单的一部分 |
| 发布状态 | 内容发布状态与任务领先状态分别记录，审核通过前不进入公开列表和真人投票 |
| 本地用户 MCP | **内容只读**：查看任务、公开作品、配置、评论和运行摘要；显式查看单题投票统计时，由平台永久关闭对应账号的该题投票资格 |
| 本地 MCP 的写操作 | 不开放投票、发评论、提交作品、发起挑战、提交预测或上报循环 |
| 真人投票与评论 | 由用户在网站完成；云端投票者的输出属于预测，不计入真人票数 |
| 跳过投票查看统计 | 网站用户与 MCP 均可选择；返回统计前按“账号 × 任务”永久取消之后对该题投票的资格，已有有效票保留 |
| 学习成果 | 保存为平台管理的云端经验、提示词、skill、评判标准或示例，仍不修改模型权重 |
| 运行费用与额度 | 云端模型调用由平台管理额度与运行预算；面向用户的计费方式另行确定 |
| 外部与内部能力 | 用户 token 不拥有内容写入、投票或云端控制权限；查看统计导致的资格记录由平台统一执行，内部云端权限独立 |

### 比赛要求如何进入产品故事

官方要求项目使用至少一个 NVIDIA 开源模型，并运行于 Nebius Token Factory 或 Nebius AI Cloud；运行时调用 Token Factory 推理 API 也符合规则对“运行于 Nebius”的定义。[来源：官方规则，Project Requirements](https://nebiusglobalaihackathon.devpost.com/rules)

本方案把模型使用落实到云端生成或评判的真实业务步骤，并在运行记录中保留实际模型与服务来源。至少一个核心角色采用符合赛事要求的 NVIDIA 开源模型，具体角色组合和型号待选定。这是本项目的交互设计；赛事的最低要求并非所有角色必须使用同一种模型。

### 本稿采用的设计默认

以下是为形成完整故事而提出的产品默认，可在评审时调整：

- MVP 由平台管理员在官方后台主动发起云端挑战；后续自动调度也只由官方后台配置。任务发布、作品上传和用户浏览均不直接触发云端运行。
- 每次挑战独立记录目标任务版本、生成者配置、投票者配置、材料版本及轮数 / 预算上限。
- 最终候选通过作品模块检查后登记为待审核作品，审核通过才公开并进入真人投票；中间稿保留在运行记录中。
- MVP 记录真人反馈并形成可供下次运行使用的样本；自动重新学习、批量再挑战放在 V1。
- 网站支持提交双方作品创建任务、单独追加人类或 agent 作品，以及浏览、投票、评论。外部 REST 若同步提供用户能力，与只读 MCP 保持相同范围。

## 2. 用户、模块与关键概念

### 用户与职责

| 参与者 | 目标与职责 |
| --- | --- |
| 发布者 | 提交任务及人类、agent 双方作品，在上传时设置授权，查看审核结果与公开云端进度 |
| 追加参选者 | 任意平台用户，均可向任何公开可见任务追加作品；逐件设置授权，新增作品独立走发布流程 |
| 真人投票者 / 评论者 | 匿名比较作品、表达真实偏好、参与讨论 |
| 本地 MCP 用户 | 在自己的工具中阅读平台内容，必要时打开网站参与 |
| 云端生成者 | 根据任务、可用经验和有限反馈生成或改进候选作品 |
| 云端投票者 | 学习人类偏好，对验证集和匿名候选作品对作出预测 |
| 平台管理员 | 在管理员 Dashboard 中完成日常内容审核、举报处理、云端挑战启动与管理、运行异常处理和额度查看 |

云端角色是系统执行职责，不是可以给自己作品投票的用户账号。

### 模块之间交接什么

| 模块 | 提供给云端流程 | 接收云端流程的结果 |
| --- | --- | --- |
| 任务模块 | 已发布任务的说明、分类、交付要求、素材、版本与领先状态 | 关联挑战记录和最终作品；不接收 agent 对领先状态的直接修改 |
| 作品与配置模块 | 可用作品、授权状态、公开配置及版本 | 候选作品、最终作品、实际生成配置与运行关联 |
| 发布与审核模块 | 任务和作品的发布状态、审核结果与可用范围 | 新任务及双方初始作品、追加作品、云端最终作品的待审版本；通过后才开放评审 |
| 学习材料模块 | 按状态和授权筛选的材料；分开的训练集、验证集 | 真人反馈样本的引用与适用范围 |
| 经验库 | 角色有权使用的 skill、提示词、评判标准或示例版本 | 学习产生的新版本及其来源、验证记录 |
| 验证与匿名评测模块 | 无正确答案的验证题；去除来源的 A / B 作品对 | 投票者预测、简短理由；由模块独立评分并还原比较结果 |
| 云端运行管理 | 已核准的运行目标、角色配置、阶段与额度 | 阶段进度、候选引用、使用量、错误、终止原因与最终结果 |
| 真人投票与评论模块 | 达到条件的人类偏好样本、可用评论 | 待真人投票的最终作品关联；不接收云端角色的人类票 |
| 统计查看与投票资格模块 | 账号在具体任务上的投票资格与可见统计 | 网站 / MCP 显式查看统计请求；先永久关闭该题投票资格，再返回统计，不产生选票 |
| 状态与看板模块 | 当前任务状态及历史记录 | 依据真人投票计算的状态变化、翻转事件和运行统计 |
| 推荐与热度模块 | 已发布任务的推荐列表、热度顺序与允许公开的摘要 | 有效参与信号及官方推荐配置；不直接启动云端 agent |
| 用户网站 / 只读 MCP | 用户可查看的任务及公开运行信息 | 展示状态与结果；普通用户无云端运行控制入口 |
| 管理员 Dashboard（官方后台） | 平台管理员身份、待处理事项与已核准配置 | 日常审核、举报处理、创建 / 取消 / 重跑云端挑战、额度调整及操作记录 |

### 五类状态分别表达什么

| 对象 | 状态含义 |
| --- | --- |
| 内容发布状态 | 草稿 / 待审核 / 审核驳回 / 已发布 / 已下架，适用于任务和作品的公开流程 |
| 账号在任务上的投票资格 | 可投票 / 已查看统计而永久不可投票；按账号与任务共同记录，独立于登录会话、token、作品对和任务版本 |
| 任务状态 | 待定 / 人类领先 / agent 领先，只由满足规则的真人投票决定 |
| 挑战运行状态 | 等待执行、准备材料、学习、验证、生成、评判、改进、登记作品、待内容审核、已开放真人投票，或无法继续、失败、取消等运行结果 |
| 作品投票结果 | 真人对具体作品对的偏好，以及该结果是否已有足够票数支持 |

“云端投票者预测获胜”“作品已提交”“任务翻转”为三个不同事件。达到轮数上限后提交作品，也不表示云端投票者认为它获胜。

### 发布状态机与审核边界

本文用“审核”表示平台管理员的发布检查，用“真人投票”表示用户比较作品。公开可见任务的发布审核已经完成，追加作品不重复审核原任务。

发布主流程为：**草稿 → 待审核 → 已发布**；审核未通过则为 **待审核 → 审核驳回 → 修改后重新待审核**。已发布内容可由官方下架；下架后如需恢复，重新审核。

- 新任务与初始人类、agent 双方作品一起提交；任务及双方作品都通过审核才公开，缺少任一方不能发布。
- 任务公开可见就意味着任务已通过审核。所有用户都可向任何可见任务追加作品；追加行为不让已有任务重新送审或回退为待审核，只有新增作品按自身发布流程处理。
- 待审、驳回和下架内容不进入公开任务列表、公开 MCP 查询、投票候选或云端学习材料；提交者在自己的提交记录中查看状态和原因，官方后台可处理。
- 影响评审的作品替换或任务内容修改形成新版本并重新审核；旧版继续展示还是暂时下架的策略待定，审核前不以新内容替换公开版本。
- 云端产出的最终作品同样需要审核。文件、压缩包和链接均属于审核对象；文件接收成功或云端生成完成不等于已发布。

### 查看统计与投票资格

资格转换为：**可投票 → 明确选择查看统计 → 该任务永久不可投票**，没有恢复路径。网站与 MCP 共用一份账号级记录；投票是否成功还需满足真人身份、内容已发布等其他条件。

普通任务浏览默认不附带具体投票统计。用户可在网站选择“跳过投票并查看统计”，或让 MCP 显式读取统计；入口须说明会永久失去这道题的投票权。平台先保存资格变化，再返回统计。任务新增作品、修改版本、切换作品对、换设备、换 token 或重新登录都不能恢复资格。

统计包括单题及作品对的得票数、分布、比例和胜率。已有有效票保留；为避免知晓统计后继续投票，本稿对“投票后再查看统计”也采用禁止之后新增该题投票的口径。任务基础状态标签与全站 / 分类汇总不触发该限制，展开具体单题统计时才触发；这些入口不能夹带受限统计数据。

## 3. 用户故事

### A. 账号、发布与作品管理

#### US-01 注册与登录

**作为**平台用户，**我希望**注册并登录账号，**以便**发布内容、参与真人投票和管理自己的接入凭证。

- 版本：MVP
- 交互模块：网站、账号

**验收标准**

1. 用户可以完成注册、登录，并获得明确的失败反馈。
2. 内容提交、投票和评论关联相应用户账号；云端运行的发起与控制操作关联平台管理员身份。
3. 真人投票和查看单题投票统计必须识别到账号；匿名访客查看统计前先登录，以便记录永久资格变化。其他浏览行为的登录要求另行确定。

#### US-02 管理只读 MCP token

**作为**本地 MCP 用户，**我希望**生成和吊销只读 token，**以便**在自己的工具中查看平台内容并控制访问权限。

- 版本：MVP
- 交互模块：账号、MCP 入口

**验收标准**

1. 用户可以生成自己的 token，并用于身份鉴别和读取获准查看的内容。
2. Token 不拥有投票、评论发布、作品提交、学习预测提交或云端运行控制权限。
3. 吊销后，后续鉴权请求被拒绝；其他用户不能管理该 token。
4. 用户 token 不能冒充云端生成者、投票者或内部评测模块。
5. 同一账号的所有 token 共用该账号的任务投票资格；经 MCP 查看统计后，网站也不可再投该题，吊销或更换 token 不重置资格。

#### US-03 提交双方作品并发布任务

**作为**发布者，**我希望**提交任务以及人类和 agent 双方的作品并通过审核，**以便**让其他人基于完整的对照参与评审。

- 版本：MVP
- 交互模块：网站、任务、作品上传、授权、发布审核

**验收标准**

1. 提交标题、说明、分类、交付物要求和素材，并且至少提供一件人类作品和一件 agent 作品；缺少任一方时不能提交发布审核。Agent 作品必须带配置清单，不能留空等待官方云端补齐。
2. 明确支持直接输入文本，以及常见文档、图片、音视频、代码文件、压缩包和链接。格式示例包括 TXT / Markdown / PDF / DOCX / XLSX / PPTX、JPG / PNG / WEBP / GIF、MP3 / WAV / MP4、常见代码文件、ZIP / 7z / RAR；单件作品可由多个附件和链接组成。
3. 任务素材、人类作品和 agent 作品分别归类；上传时填写作品来源、相关授权及 agent 配置，不能把素材附件误计为任一方作品。
4. 草稿可以暂存不完整内容；提交后进入待审核。任务与双方初始作品均通过审核才进入已发布状态，并开放真人投票；此时票数不足的领先状态为待定。
5. 文件、压缩包、链接支持接收、访问和审核；大小、数量、链接可访问性、在线预览及云端可处理格式的细节另定，不再把是否支持这些上传类型列为待定。
6. 普通用户提交任务不启动或控制云端 agent；官方后续如需挑战，由官方后台另行选择已发布任务。

#### US-04 在作品上传时设置学习与比较授权

**作为**作品提交者，**我希望**在上传作品的同一表单中设置学习与比较授权，**以便**逐件决定作品是否参与云端 agent 改进。

- 版本：MVP
- 交互模块：作品上传表单、作品授权、发布审核、学习材料、云端运行

**验收标准**

1. 初始任务双方作品和追加作品均使用包含授权选项的上传流程；授权绑定到具体作品及版本，不设置成覆盖任务下所有投稿的总开关。
2. 人类作品的上传区域明确提供“允许平台云端 agent 用于学习与比较”选项，说明涉及偏好训练、验证及对抗参照，并与文件、压缩包或链接一起保存。追加人类作品也须独立记录作者选择。
3. Agent 作品在上传时一并填写配置及提示词 / skill 正文公开选项，继续按配置公开范围提供学习材料；人类作品学习授权与 agent 配置公开范围分别记录。
4. 未授权的人类作品不进入云端学习或作为对抗参照，但审核通过后仍可参加真人投票。审核通过不自动授予学习权限，允许学习也不替代发布审核。
5. 官方后台选取任务、云端领取材料时同时检查发布状态与授权；缺少材料时返回原因，不用未授权内容补齐。
6. 授权默认值、能否撤回及对既有经验的影响待确认；上传作品或勾选授权均不赋予用户任何云端运行控制权。

#### US-05 单独追加人类或 agent 参赛作品

**作为**任意平台用户，**我希望**向任何公开可见任务单独追加人类或 agent 作品，**以便**不受任务归属限制地参与挑战。

- 版本：MVP
- 交互模块：网站 / 官方云端运行、作品上传、授权与配置、发布审核、真人投票

**验收标准**

1. 所有用户都可以在网站向任何公开可见任务追加作品，无需是任务发布者，也无需任务作者邀请或批准；人类或 agent 作品可以单独提交，沿用 US-03 的文件、压缩包和链接支持范围。
2. 每件作品记录目标任务、来源、提交者与版本；人类作品在上传时设置学习授权，agent 作品附实际配置及正文公开选项。
3. 可见任务本身已通过审核，追加不触发原任务再次审核。仅新增作品进入自己的待审核流程，通过后加入公开作品与真人投票候选列表；驳回时向投稿者说明原因，原任务保持已发布。
4. 官方云端运行也可登记最终 agent 候选，关联官方运行与实际配置，遵循相同检查和审核流程。用户 MCP 不开放作品提交。
5. 缺少必要授权选择或 agent 配置、交付物无效、与已有作品高度相似时返回明确结果；相似度阈值另定。
6. 同一官方运行的同一最终候选重复登记时返回已有作品及审核状态，不产生多份作品；登记成功不等于已发布或已获胜。
7. 因查看统计失去该题投票权的用户仍可追加作品和按规则评论；投稿权限与投票资格分别管理。MCP 仍不开放投稿能力。

#### US-06 展示实际配置与公开范围

**作为**作品查看者，**我希望**了解作品实际使用的生成配置，**以便**比较不同方法并理解作品来源。

- 版本：MVP
- 交互模块：作品、配置、云端运行、经验库

**验收标准**

1. Agent 作品记录模型、提示词、harness、skill 列表和其他参数；云端作品由实际运行结果补全，不能仅用计划配置替代。
2. 云端投票者模型、评判标准与验证结果归入运行记录，不混同为作品生成模型。
3. 提示词和 skill 正文遵守公开设置；网站和 MCP 都只展示允许公开的部分。
4. 模型或配置发生变化时保留版本关联，使最终作品能追溯到真正产出它的配置。

### B. 首页发现、真人投票与看板排行

#### US-37 在推荐首页无限发现任务

**作为**网站浏览者，**我希望**打开首页就连续看到平台推荐的任务，**以便**不断发现值得阅读、讨论或评审的内容。

- 版本：MVP
- 交互模块：首页、平台推荐、已发布任务、内容可见性

**验收标准**

1. 网站首页直接是推荐发现流，任务按照平台推荐结果展示；看板与排行榜通过单独导航入口进入同一页面。
2. 推荐流只包含已审核发布的任务；卡片可展示标题、摘要、分类、作品形式及允许公开的信息，点击进入任务页。
3. 向下滚动持续加载下一批，在一次连续浏览中避免重复卡片；加载中、失败重试、暂无推荐和已浏览完当前内容均有明确状态。
4. 平台维护推荐规则或运营推荐配置；具体排序策略另定。用户浏览和滚动不启动任何云端 agent。
5. 卡片与预加载默认不带具体单题投票统计，也不自动放弃投票权；用户显式查看统计时才执行 US-36。

#### US-07 在任务页查看作品和云端进度

**作为**任务关注者，**我希望**在同一任务页查看作品、真人结果及云端挑战进度，**以便**了解挑战进行到了哪里。

- 版本：MVP
- 交互模块：任务、作品、运行记录、投票汇总

**验收标准**

1. 公开任务页展示已发布任务及已审核发布的作品、配置对比、评论和基础领先状态；具体投票统计通过 US-36 的入口读取，不默认嵌入页面数据。提交者在自己的提交记录查看待审或驳回内容。
2. 展示云端挑战的公开阶段、当前轮次和最终作品链接；无法继续时显示适合公开的原因。
3. 公开摘要不包含未公开配置、验证集答案、完整评判标准或受限运行材料。
4. 进入匿名投票时，评审视图不显示作品来源及云端预测；详情页已知信息的处理边界需在产品评审时确定。
5. 普通用户仅查看公开云端进度，不显示启动、取消、重跑、选择角色配置或调整预算的控件。
6. 展示当前账号对该题的投票资格；已经查看统计的用户显示永久不可投票原因，仍可浏览与按网站规则评论。

#### US-08 匿名投票并揭晓来源

**作为**真人投票者，**我希望**先比较匿名作品，再表达偏好和查看来源，**以便**根据作品本身作出判断。

- 版本：MVP
- 交互模块：网站、匿名配对、真人投票、作品

**验收标准**

1. 网站从同一已发布任务中选取两件已审核发布的作品，展示任务背景并隐藏作者、来源、模型配置和云端预测；待审、驳回或下架作品不可投票。
2. 用户可以选择 A、B 或平局；提交成功后揭晓作者、来源和可公开配置。
3. 票归属于实际投票用户；云端角色和只读 MCP 均不能调用真人投票能力。
4. 提交每张票时由平台检查账号在该任务上的资格；已选择查看统计则拒绝后续投票，不能只隐藏前端按钮。
5. 配对候选范围、重复投票和真人识别规则另行确定；无论如何配置，不能恢复已永久失去的资格。

#### US-36 跳过投票查看统计并永久放弃该题投票权

**作为**网站用户或本地 MCP 用户，**我希望**可以直接查看一道题的投票统计，**以便**在不参与投票的情况下了解人类的判断，同时接受永久失去该题投票权的后果。

- 版本：MVP
- 交互模块：网站 / MCP、账号、统计查询、任务投票资格、真人投票

**验收标准**

1. 网站提供明确入口，告知“查看后将永久失去这道题的投票权”；MCP 工具说明和显式统计读取选项表达相同后果，不能因默认查询或预取悄悄触发。
2. 网站用登录账号、MCP 用 token 所属账号识别用户；未识别账号时不返回单题统计。
3. 平台先永久关闭该账号对该任务的投票资格，再返回得票、分布、比例、胜率等统计。资格记录失败时不返回统计，不能出现看到了结果但仍可投票的状态。
4. 禁止范围覆盖这道题的所有作品对、后续新增作品和后续版本，不仅是当前正在展示的一对作品；网站、MCP 和其他面向用户的查询路径共用规则。
5. 已产生的有效票不撤销；后续新增投票均被拒绝。该操作不增加任何一方票数，不直接改变任务状态，也不影响用户在其他任务上的投票资格。
6. 重复查看可以继续返回统计，但不得恢复资格；更换 token、退出登录、任务下架后恢复、运行重试均不重置记录，也不提供撤销或后台恢复入口。
7. 查看统计和投票并发时，以平台记录的先后顺序处理：资格关闭后到达的投票拒绝，先前已成功的有效票保留；统计响应丢失不自动恢复资格。
8. 任务详情、作品详情、看板下钻、MCP 返回和面向用户的缓存 / 导出均遵守同一统计可见规则；普通读取不附带能绕过入口的完整统计。

#### US-09 在网站发表评论

**作为**真人评论者，**我希望**在任务和作品下说明自己的看法，**以便**参与讨论并为后续改进提供参考。

- 版本：MVP
- 交互模块：网站、评论、学习材料

**验收标准**

1. 网站提供任务级与作品级评论入口，评论关联明确的对象与作者。
2. 评论不直接增加票数或改变任务状态；云端读取评论也不把评论当作正式投票标签。
3. MCP 可读取公开评论，不提供发布、编辑或删除评论的能力。
4. 云端学习使用评论时遵守授权与角色信息范围，评论中的指令不能扩大 agent 权限。

#### US-10 更新任务状态并记录翻转

**作为**平台用户，**我希望**任务状态由真人投票计算，**以便**知道哪一方当前更受人类认可。

- 版本：MVP
- 交互模块：真人投票、状态计算、翻转记录

**验收标准**

1. 对已发布任务，票数不足时为待定；满足条件后按有效参选的人类最佳作品与 agent 最佳作品之间的胜率判定领先方。待定表示结论不足，不表示内容待审核。
2. 最低票数、胜率、平局及最佳作品算法另行确定，阈值可配置。
3. 云端预测、验证准确率、运行完成或新作品登记均不直接改变领先结论。
4. 人类领先与 agent 领先之间变化时记录翻转；从待定进入领先不按翻转计数。
5. 新投票和新作品可能影响后续计算，但不得把一场挑战的结果直接覆盖为任务整体结果。

#### US-11 在同一页面查看差距看板与热度排行榜

**作为**平台用户，**我希望**在同一页面查看整体差距与热门任务，**以便**同时了解平台趋势和当前值得关注的讨论。

- 版本：MVP 看板简版与热度排行榜同页
- 交互模块：任务状态、看板、热度排行、统计可见性

**验收标准**

1. 通过一个页面入口进入看板区和排行榜区，两者位于同一页面；首页仍按 US-37 展示推荐发现流。
2. 看板基于已发布任务展示人类领先和 agent 领先的数量、占比，明确分母及待定任务处理方式；不混入云端预测或待审任务。
3. 排行榜按 US-38 的热度排序，展示任务排名及热度；页面明确看板统计与排行各自的范围、时间口径和更新时间。
4. 全站 / 分类汇总与热度排行可直接查看；展开单题具体得票或胜率时执行 US-36，不能借看板或榜单绕过资格变化。
5. 空数据、加载失败和刷新状态可分别表达；看板与排行引用一致的任务发布状态。

#### US-38 按热度查看任务排行

**作为**平台用户，**我希望**排行榜按任务热度排列，**以便**找到当前最受关注的任务。

- 版本：MVP
- 交互模块：有效参与记录、热度计算、同页排行榜、任务详情

**验收标准**

1. 排行对象为已发布任务，按统一热度分降序展示；热度与“人类领先 / agent 领先”的判断分别计算和展示。
2. 热度可采用有效独立访问、真人投票、评论、追加作品等参与信号，并考虑时效；具体信号、权重、时间窗口与防刷规则待定，不在本文虚设公式。
3. 云端内部生成轮数、自评结果、重复请求和无效操作不能直接冒充人类参与；热度不等同作品胜率或投票者准确率。
4. 卡片展示排名、热度、任务摘要与入口；不默认公开具体得票分布或胜率。查看该题投票统计仍执行 US-36。
5. 热度变化和内容下架后更新榜单；同分排序和刷新周期待定，页面标明当前榜单的统计范围与更新时间。

#### US-12 在看板排行页查看差距变化与翻转历史

**作为**平台用户，**我希望**按时间、分类查看差距变化及翻转事件，**以便**了解哪些领域正在变化。

- 版本：V1
- 交互模块：状态历史、翻转记录、看板

**验收标准**

1. 在看板与热度排行共用的页面内，增强双方领先数量、占比的时间变化与分类筛选，不另设一个独立看板页面。
2. 翻转记录关联任务、发生时间、变化方向及相关作品。
3. 若作品来自云端，可查看对应公开运行摘要，区分“怎么生成”和“真人如何评价”。
4. 榜单继续按热度排序，查看单题详细统计继续遵守 US-36。

### C. 本地 MCP 只读访问

#### US-13 接入只读 MCP

**作为**本地 MCP 用户，**我希望**把自己的工具连接到平台，**以便**在当前工作环境中阅读任务与讨论。

- 版本：MVP
- 交互模块：账号、MCP、任务查询

**验收标准**

1. 提供 token 接入说明和只读能力说明；流程 skill 如提供，也只描述阅读与跳转网站的流程。
2. MVP 工具范围为 `list_tasks`、`get_task`；默认返回任务与公开内容，单题投票统计须显式选择查看并接受永久失去该题投票权。
3. 不暴露投票、发评论、作品提交、学习材料批量领取、预测提交、循环上报或云端运行控制工具。
4. 需要投票或发评论时返回网站入口，并说明当前投票资格；MCP 不提交这些操作，也不控制云端 agent。
5. “内容只读”不代表查看统计没有后果：资格变化由平台执行，工具须披露该副作用；客户端只有明确收到用户查看统计的意图并告知后果后才请求，不因阅读任务而自动选择。

#### US-14 查找任务并阅读公开内容

**作为**本地 MCP 用户，**我希望**按状态、分类和更新时间查找 task 并阅读内容，**以便**选择值得关注的挑战。

- 版本：MVP
- 交互模块：MCP、任务、作品、评论、公开运行摘要、统计可见性与投票资格

**验收标准**

1. `list_tasks` 支持状态、分类和更新时间筛选。
2. `get_task` 默认返回已发布任务、作品、公开配置、评论、投票资格与公开运行摘要；不返回具体得票和胜率，不泄露待审作品内容。
3. 不返回服务端凭证、受限配置、训练 / 验证材料包、验证答案或角色内部上下文。
4. 读取权限不等于获得学习授权；内容失效或访问受限时返回明确结果。
5. 显式请求单题统计时执行 US-36，返回统计及“该题永久不可投票”的结果；后续在网站也无法补投，其他任务资格不受影响。

### D. 云端 agent 与业务模块的交互

以下沿用已有故事编号，并增加 US-30～US-35 补齐发起、角色输入输出、异常与赛事模型使用的交互。

#### US-30 平台管理员通过 Dashboard 启动云端挑战

**作为**平台管理员，**我希望**在管理员 Dashboard 中选择公开可见任务并启动云端挑战，**以便**按平台安排产出新的参赛作品。

- 版本：MVP
- 交互模块：官方后台 → 任务 / 发布状态 / 配置 / 额度 → 云端运行

**验收标准**

1. 只有平台管理员身份可以在管理员 Dashboard 中选择任务、生成者 / 投票者配置及轮数与预算上限，并提交启动请求。
2. 平台核对平台管理员权限、任务已发布状态、版本有效性、作品类型支持、材料授权和运行额度。
3. 接受后创建可追踪的运行记录，固定本次任务、配置和数据版本；官方后台获得管理信息，用户任务页仅获得允许公开的运行摘要。
4. 同一发起请求重复提交不创建多份运行；输入不足或额度不足时直接说明，不显示为正在生成。
5. 普通用户通过网站、MCP、用户 token 或直接请求内部能力均不能启动运行，也不能通过发布任务、追加作品、投票或勾选授权隐式触发。
6. 后续如支持定时或事件触发，只能由官方后台配置和执行；公开页面没有“申请后立即启动”或代替后台控制的入口。

#### US-15 按状态为云端运行准备材料

**作为**平台管理员，**我希望**系统按任务状态、授权和运行目标准备材料，**以便**每次官方挑战进入适合的流程。

- 版本：MVP
- 交互模块：云端运行 → 任务 / 作品授权 / 学习材料 → 相应角色

**验收标准**

1. 已发布但领先结论待定的任务不提供偏好学习材料；官方可仅根据任务说明和素材生成追加作品，审核通过后交真人投票。任务发布所需的双方初始作品已由发布者提供。
2. Agent 领先任务可读取获胜 agent 作品、公开配置和可用人类反馈，走 US-16 的经验提炼路径。
3. 人类领先任务准备已授权的训练 / 验证材料与对抗参照，先检查投票者是否已有匹配的有效验证记录，否则进入学习与验证。
4. 生成者只获得其职责需要的任务数据和可用经验；人类参照与正确答案分别交给相应受限模块。
5. 发布状态、版本或授权变化不静默替换运行中的材料；继续之前检查是否仍有效，无法满足时停止或等待官方后台处理，不由普通用户重启。

#### US-16 从领先的 agent 作品提炼云端经验

**作为**希望改进后续作品的任务参与者，**我希望**云端流程能从已获人类认可的 agent 作品中提炼经验，**以便**后续生成使用有依据的方法。

- 版本：MVP
- 交互模块：学习材料 → 云端学习步骤 → 经验库 → 生成者

**验收标准**

1. 读取获胜 agent 作品、公开配置、投票统计和可用评论，保留任务与作品来源。
2. 提炼结果作为经验库的新版本保存，可表现为 skill、提示词或示例，不修改模型权重。
3. 后续生成记录所引用的经验版本；经验被哪些作品使用可以追溯。
4. 只向生成者提供允许其接收的内容；不得通过经验或评论转交当前对抗参照的人类原文或完整评判标准。
5. 复用经验不表示必然获胜，最终仍经真人投票；跨任务自动推广属于后续扩展。

#### US-17 学习云端投票者的评判标准

**作为**云端投票者，**我希望**获得已授权作品对及人类投票结果，**以便**总结人类偏好并形成可验证的评判标准。

- 版本：MVP
- 交互模块：学习材料 → 投票者 → 经验库 / 验证模块

**验收标准**

1. 训练材料来自目标及同分类任务，包含作品对与人类偏好结果；涉及的人类作品均已授权。
2. 训练集与验证集分开标识，验证答案不进入学习上下文或经验内容；样本不足时说明无法完成验证。
3. 投票者输出评判标准版本，关联模型、配置与训练材料版本。
4. 新标准先标记为待验证，不直接替换正在运行的已验证标准；生成者不能读取完整标准。

#### US-18 独立验证云端投票者

**作为**平台管理员，**我希望**平台独立检验投票者能否预测人类偏好，**以便**只让达到条件的投票者指导对抗。

- 版本：MVP
- 交互模块：验证模块 → 投票者 → 验证评分 → 云端运行

**验收标准**

1. 验证模块提供匿名作品对，不提供人类正确答案、公开任务结果或可用于查询答案的关联信息。
2. 投票者提交各对作品的预测；评分由独立模块使用保留的人类结果完成，记录准确率与样本范围。
3. 达到配置阈值后，当前模型、提示词、评判标准与数据版本的组合获得进入对抗的资格；未达到时返回失败原因，不进入对抗。
4. 模型或评判标准改变后重新验证，不沿用旧组合的合格结论；重试学习或验证受运行预算与次数约束。
5. 预测不进入真人票池；平局、缺失预测、验证集更新和重复验证口径待定。

#### US-32 为生成者交付任务并接收候选作品

**作为**云端生成者，**我希望**收到明确的任务交付要求、可用素材和适当反馈，**以便**产出系统可以登记与评审的候选作品。

- 版本：MVP
- 交互模块：任务 / 经验库 / 云端运行 → 生成者 → 候选作品模块

**验收标准**

1. 初次生成获得任务说明、交付要求、任务素材、允许使用的经验及当前限制，不获得人类参照原文或完整评判标准。
2. 改进时额外获得自己的上一版作品，以及上一轮允许传递的判断和简短理由。
3. 结果包含候选内容或交付物引用、候选版本及实际生成配置；记录到本次运行，而非立即把每个中间稿公开参赛。
4. 缺少交付物、格式不支持或生成失败时返回明确失败结果；仅有“生成成功”的文字不算有效候选。
5. 当模型能力不支持目标格式时说明不支持，不用静态占位物冒充已生成成果。

#### US-33 为投票者构造匿名比较并接收反馈

**作为**云端投票者，**我希望**只看到匿名作品对、任务背景和自己的评判标准，**以便**预测人类偏好并给出可用于改进的理由。

- 版本：MVP
- 交互模块：候选作品 / 授权参照 → 匿名评测 → 投票者 → 反馈过滤 → 生成者

**验收标准**

1. 评测模块把候选与获授权的人类参照组成 A / B 对，随机位置并隐藏作者、模型、来源和既有票数。
2. 投票者返回 A、B 或平局及简短理由；它不能得到哪件是本轮生成作品的映射。
3. 评测模块保留映射并还原候选的比较结果，反馈给运行管理；生成者只接收与改进有关的判断和理由。
4. 传给生成者的理由不引用或复现人类作品原文，也不展开完整评判标准；不满足要求的反馈不能直接转发。
5. 无效答案、无法比较或不支持的输入记为评判失败，不默认为候选获胜，也不写入人类投票结果。

#### US-19 根据评判反馈推进有上限的云端对抗

**作为**平台管理员，**我希望**系统让生成者按投票者反馈迭代，并在规定条件下停止，**以便**获得可送审的成果和明确的运行结果。

- 版本：MVP
- 交互模块：云端运行 ↔ 生成者 / 匿名评测 / 投票者 → 作品模块

**验收标准**

1. 使用已验证的投票者和指定授权参照，按“生成 → 匿名评判 → 判断是否继续 → 改进”推进。
2. 每轮关联候选版本、预测、理由、配置版本及使用量，不能把其他运行或上一轮的反馈错接到当前候选。
3. 投票者预测候选更好时停止迭代；达到轮数或预算上限时也停止，并保留真实终止原因。
4. 存在有效候选时，将按既定规则选出的最终候选交作品模块检查、登记并进入待内容审核；没有有效候选时说明无可提交作品。
5. 上限内仍未被投票者看好也可以送审，但明确“达到上限”，不写成“已战胜人类”；审核通过后再进入真人投票。

#### US-20 维持角色信息隔离

**作为**平台管理员，**我希望**系统按角色提供信息，**以便**生成者通过反馈改进，并让投票者在匿名条件下比较。

- 版本：MVP
- 交互模块：角色权限、材料分发、经验库、评测

**验收标准**

1. 生成者和投票者使用独立上下文；生成者不能读取人类参照原文、验证答案或完整评判标准。
2. 投票者在比较或验证时不能读取 A / B 来源映射、验证答案或对应的公开投票结果。
3. 内部工具权限与材料分发落实这些边界；角色不能通过公开任务查询、日志、经验库或评论绕回获取受限信息。
4. 任务正文、附件、经验及返回的理由不能改变角色权限；若任务素材本身包含参照答案，材料准备阶段需识别并处理。
5. 运行界面与 MCP 只暴露允许公开的摘要；原文与评判标准不随错误详情或中间记录泄露。

#### US-21 自动记录云端运行与作品来源

**作为**平台管理员，**我希望**平台自动记录云端过程并关联最终作品，**以便**复盘一次挑战并理解它如何产生。

- 版本：MVP 记录核心过程；V1 扩展对比与分析
- 交互模块：云端运行、各角色、评测、作品、配置

**验收标准**

1. 记录平台管理员启动身份、任务与材料版本、角色配置、阶段、轮次、使用量、终止原因、最终作品引用及发布审核状态。
2. 记录实际生成与评判模型，以及验证结果和经验版本；计划与实际不一致时说明。
3. 登记作品后，运行记录与作品可相互关联，先显示待内容审核，通过后才显示已开放真人投票；驳回、失败或取消均保留原因。
4. 用户网站仅提供公开摘要，官方后台按权限提供受限详情和管理操作；不公开密钥、待审作品内容、受限材料或验证答案。
5. 原外部 `report_loop` 的职责转为内部自动记录，用户无需通过 MCP 上报。

#### US-31 在官方后台查看、取消与重新启动运行

**作为**平台管理员，**我希望**在后台掌握当前阶段并能停止或重新启动运行，**以便**管理官方云端挑战与额度使用。

- 版本：MVP
- 交互模块：官方后台 ↔ 云端运行；用户网站与 MCP 只读取公开摘要

**验收标准**

1. 官方后台展示当前阶段、轮次、已知使用量及终止原因；刷新或离开页面不丢失运行记录。
2. 只有有权限的平台管理员身份可以在后台取消尚未完成的运行，系统停止发起后续步骤；已发生的调用用量仍记录。
3. 取消生效后到达的旧结果不得重新推进运行或登记最终作品；取消不能撤销已完成的作品登记，两者先后需有明确结果。
4. 官方后台重新启动时创建关联的新运行，重新检查发布状态、材料与额度，不覆盖历史记录。
5. 普通用户无论是否为任务作者，都不能启动、取消、重启、调整配置或改变预算；用户网站与 MCP 均只有公开进度展示。
6. 作品登记后由内容审核流程处理其发布；审核通过后由任务页承接真人投票。取消云端执行不替代作品撤回、下架或审核操作。

#### US-34 在失败或失效时反馈明确结果

**作为**平台管理员，**我希望**云端步骤失败时系统给出可理解的结果，**以便**知道作品是否送审以及是否需要重试。

- 版本：MVP
- 交互模块：云端运行、模型调用结果、材料、评测、作品

**验收标准**

1. 模型不可用、超时、材料不足、验证未通过、授权失效及作品检查失败分别记录原因，不把失败显示成获胜或已参赛。
2. 重试遵守本次预算和次数限制；重复或迟到的结果不重复扣记同一次已报告使用量，也不重复登记作品。
3. 已取消、失败或结束的运行不因迟到结果恢复推进；新任务版本不能静默接收旧版本运行的作品。
4. 登记作品的响应丢失时先确认登记结果，再决定重试；避免出现重复参赛作品。
5. 官方后台的错误信息给出下一步，例如更换已验证配置、补充材料或重新启动；普通用户只看到公开状态，不获得控制入口或受限内容。

#### US-22 将真人投票回流到云端学习

**作为**希望持续改进作品的参与者，**我希望**平台把最终作品的真实人类反馈关联回云端运行，**以便**修正 agent 的判断与生成方法。

- 版本：MVP 记录反馈样本；V1 自动再学习与再挑战
- 交互模块：真人投票 → 反馈归集 → 学习材料 / 经验版本；真人投票 → 任务状态

**验收标准**

1. 最终作品通过审核并发布、获得足够真人票后，形成关联作品对、运行与配置版本的反馈样本；待审不开放投票，票数不足时保留为等待反馈。
2. 投票者预测候选获胜而真人更喜欢人类作品时，记录预测偏差，并在授权允许时加入后续训练材料。
3. 真人偏好生成作品时，同样保留该结果；是否引发任务翻转由状态模块按整体规则计算。
4. 新反馈形成后续材料版本，不污染本次运行用于验证的保留答案，也不改写此前验证成绩。
5. MVP 由官方后台启动的下次挑战可读取新材料；V1 自动学习或重跑也须由官方后台配置独立额度和触发策略，普通用户的单次操作不能直接启动运行。

#### US-35 在真实云端步骤中使用赛事模型

**作为**参赛团队，**我希望**云端核心步骤实际使用符合要求的模型与服务并留下可核对记录，**以便**说明产品如何满足比赛要求。

- 版本：MVP
- 交互模块：角色配置、云端执行、运行记录、作品 / 评测结果

**验收标准**

1. 至少一个生成或评判核心角色实际调用 NVIDIA 开源模型，且项目满足本节前述 Nebius 运行要求；具体角色与型号由配置明确。
2. 该调用产生的作品或预测被后续模块真实使用，不能仅在界面放置模型名称或进行无关演示调用。
3. 记录实际模型标识、服务来源、调用结果与角色职责，能从最终作品或评测记录追溯其用途；不展示服务端密钥。
4. 模型不可用或发生替换时如实记录；替换投票者后重新确认验证资格，不能继续宣称由未使用的模型完成。

赛事的模型与运行条件依据[官方规则](https://nebiusglobalaihackathon.devpost.com/rules)；上述角色安排和追溯方式为本项目的设计。

### E. 管理员 Dashboard、平台保障与后续能力

#### US-39 使用管理员 Dashboard 处理日常工作

**作为**平台管理员，**我希望**在一个管理员 Dashboard 中完成内容审核和云端挑战管理，**以便**集中处理平台每日待办、运行进度和异常。

- 版本：MVP
- 交互模块：管理员 Dashboard、账号权限、内容审核、举报、云端运行、额度与操作记录

**验收标准**

1. Dashboard 仅向平台管理员开放，与面向所有用户的看板 / 热度排行页面分别设置；用户网站和 MCP 不获得管理权限。
2. 进入后可查看待审核的新任务、追加作品、云端作品、待处理举报，以及运行中 / 失败 / 已结束的云端挑战和额度使用情况。
3. 管理员可从待办进入内容详情，执行审核通过、驳回并说明原因、举报处理或下架。已公开可见的任务视为已过审，新增投稿只处理新增作品。
4. 管理员可选择可见任务启动挑战，并在同一 Dashboard 查看阶段、轮次、实际配置、使用量、最终作品及内容审核结果。
5. 运行失败、额度不足或材料失效时显示原因；管理员可按规则取消或重新启动。迟到结果和重复登记的处理沿用 US-31、US-34，不形成另一条用户可控入口。
6. 审核和运行管理操作记录平台管理员身份、对象、时间与结果，便于日常追踪；云端作品生成完成后可在内容审核待办中继续处理其发布。

#### US-23 保持真人投票的独立性

**作为**真人参与者，**我希望**平台结论只由人类决定，**以便**看到真实的人类偏好。

- 版本：MVP
- 交互模块：账号、真人投票、云端预测、统计

**验收标准**

1. 只读 MCP 和云端角色均无真人投票权限；网站采用确定后的真人识别与防重复规则。
2. 云端验证、对抗预测、作品登记与真人投票分别记录，只有后者进入真人票数和任务胜率。
3. 评审前不向投票界面提供云端胜负预测；评论和运行标签也不替代真人判断。
4. 真人身份不覆盖 US-36 的永久资格限制；已查看该题统计的账号不得再对该题新增投票。

#### US-24 保护账号与云端数据

**作为**平台用户，**我希望**账号、作品及运行材料按权限访问，**以便**自己的受限内容不会被其他用户或无权角色读取。

- 版本：MVP 基线
- 交互模块：账号、数据库、云端角色、公开查询

**验收标准**

1. 数据库开启行级权限，受限数据按账号与职责授权访问。
2. 云端角色、用户网站操作与只读 MCP 使用各自范围的权限，不共享可任意操作系统的能力。
3. 模型服务密钥与内部凭证不进入前端代码、MCP 返回或公开运行记录。
4. 未公开正文、验证答案和角色上下文遵守 US-20 的边界。

#### US-25 管理接口限流与云端额度

**作为**平台管理员，**我希望**限制外部请求和云端运行消耗，**以便**在可用额度内持续提供服务。

- 版本：MVP 基线；V1 完善策略
- 交互模块：MCP / 用户网站、官方后台、额度、云端运行

**验收标准**

1. 外部读取、真人操作和官方后台云端启动分别适用已配置的限流规则，超限有明确反馈；限流配置不赋予普通用户运行控制权。
2. 每次运行有轮数和预算上限；额度不足不接收新运行，接近或达到限制时按停止策略处理。
3. 平台记录包括失败尝试在内的已知使用量；无法获得实际费用时不虚构精确金额。
4. 额度分配、并发限制、计费单位和用户收费方式待确定。

#### US-26 将用户内容作为受限任务数据处理

**作为**平台参与者，**我希望**任务和作品中的文字不能改写系统权限与运行规则，**以便**云端挑战按约定流程完成。

- 版本：MVP 基线
- 交互模块：内容、材料分发、云端角色、接入说明

**验收标准**

1. 任务、作品、评论和外链内容属于任务数据，不能覆盖角色权限、匿名规则、预算上限和材料范围。
2. 云端流程与外部接入说明明确这些边界；返回内容中的指令不能授予投票、泄露材料或任意调用内部能力的权限。
3. 任务本身要求的正常生成目标与夹带的越权指令分别处理，不能以“按任务执行”为由突破 US-20。

#### US-27 审核发布并处理举报

**作为**平台管理员，**我希望**审核任务与作品发布并处理用户举报，**以便**让符合要求的内容进入公开投票。

- 版本：MVP 必须具备发布审核与举报处理；V1 完善审核工具
- 交互模块：提交记录、官方审核后台、发布状态、举报、材料与运行

**验收标准**

1. 新任务及其双方初始作品、独立追加作品、官方云端最终作品均进入审核；只有通过审核的内容可以公开和参加真人投票。
2. 官方后台支持通过、驳回并说明原因，以及对已发布内容下架；处理结果记录到发布状态，提交者可查看并修改后重提。
3. 审核覆盖作品内容、附件 / 压缩包 / 链接、来源和所需配置，以及授权选项是否记录；审核不代替作者授予学习权限。
4. 网站保留举报入口，人工处理可定位内容；下架或失效状态同步影响公开查询、投票候选和后续云端取材。
5. 已运行过程、已形成经验和历史投票的处置规则另行确定，保留处理记录；具体自动检查与人工审核分工不在本文展开。

#### US-28 观察参与、运行与差距指标

**作为**平台管理员，**我希望**分别看到人类参与和云端运行结果，**以便**判断产品是否产生有效比较与改进。

- 版本：MVP 基础记录；V1 完善分析
- 交互模块：任务、作品、真人投票、MCP 访问、运行、反馈、看板

**验收标准**

1. 统计任务、作品、真人投票和翻转事件；MCP 读取不计为投票或学习完成。
2. 云端运行按实际记录统计发起、完成、失败、轮次、学习 / 验证次数和已知消耗，区分模型调用与完整运行。
3. 区分投票者预测获胜、最终提交作品和真人认可的结果，不用自评替代真实效果。
4. 原“接入 agent 数”细化为外部只读接入与云端角色运行两个口径，具体去重规则待确定。
5. 推荐发现与热度计算使用定义明确的有效参与信号；查看统计、永久放弃投票资格和云端自评均不增加真人票数。

#### US-29 增强视频预览与云端处理

**作为**作品提交者与评审者，**我希望**在已支持视频文件上传的基础上获得更好的预览与云端处理，**以便**方便地比较动态内容。

- 版本：V1
- 交互模块：作品、预览、真人投票、云端能力检查

**验收标准**

1. MVP 的通用上传范围已包含 MP4 等常见视频文件及链接，沿用作品上传授权与发布审核；V1 增强在线预览、播放与对应云端处理。
2. 官方云端生成或比较视频需对应角色具备处理能力；文件可以上传不等于每个角色都支持解析或生成。
3. 在线预览、转码、云端理解范围及大小 / 时长限制另行确定，不再把视频文件能否上传列为 V1 前置条件。

## 4. 端到端交互场景

### 场景一：从推荐首页发现任务

1. 用户打开首页，直接进入平台推荐的发现流，向下滚动连续加载已发布任务。
2. 卡片展示任务摘要和允许公开的信息，不预取单题具体投票统计，不影响投票资格。
3. 用户进入任务详情，按自己的资格选择投票，或明确选择查看统计并永久放弃该题后续投票权。
4. 用户进入“看板与排行榜”页面，在同一页查看整体差距和按热度排列的任务。

### 场景二：提交双方作品、审核后发布

1. 发布者填写任务信息，至少提交一件人类作品与一件 agent 作品，可使用文件、压缩包、链接等形式。
2. 在各作品的上传表单中记录来源、相应授权和配置；缺少任一方作品时可以保存草稿，但不能送交发布审核。
3. 任务及双方初始作品一起进入待审核；官方审核通过后公开，驳回则说明原因并允许修改重提。
4. 已发布任务进入推荐候选、公开查询与真人投票；用户提交任务不启动云端 agent。

### 场景三：所有用户向任何可见任务追加作品

1. 任意用户打开任意公开可见任务即可选择追加人类或 agent 作品，无需是任务发布者，无需任务作者邀请或批准，也无需同时提交另一方。
2. 任务可见即表示任务本身已通过审核；追加投稿不会让已有任务重新送审，任务保持已发布状态。
3. 投稿者上传作品并设置该件作品的授权或配置；只有新增作品按自己的发布流程送审，通过后加入公开参选列表，驳回时向投稿者反馈原因。
4. 该用户即使已因查看统计而失去这道题的投票权，也仍可追加作品；投稿不恢复投票资格。MCP 仍只提供内容读取，不代为投稿。

### 场景四：平台管理员通过 Dashboard 日常审核并管理云端挑战

1. **进入每日工作台。** 平台管理员登录管理员 Dashboard，查看待审核任务与作品、举报、云端挑战状态、异常和额度使用情况。该页面与公开的看板 / 排行榜分开，普通用户无管理权限。
2. **处理日常审核。** 管理员审核新任务及双方初始作品、独立追加作品和云端生成作品，执行通过、驳回及原因反馈，按需要处理举报和下架。任何公开可见任务本身已过审，不因新投稿重复审核原任务。
3. **启动云端挑战。** 管理员在 Dashboard 选择已公开可见任务、生成者 / 投票者配置及轮数与预算，确认材料可用后启动。任务作者及其他普通用户均不能执行这一步。
4. **查看运行过程。** Dashboard 展示阶段、轮次、配置和消耗；待定任务只追加生成，agent 领先任务可提炼经验，人类领先任务准备授权材料、验证投票者，再按匿名对抗流程运行。
5. **处理失败与停止。** 模型失败、预算不足或材料失效时，管理员查看原因并按规则取消或重新启动；重新启动创建关联的新运行并重新检查任务、授权和额度。取消或结束后的迟到结果不继续推进，也不登记新作品。
6. **处理产出与发布。** 最终候选进入 Dashboard 的作品审核待办，通过后公开并开放真人投票。登记响应丢失或重试时先找回已有作品及审核状态，避免重复作品和绕过审核。
7. **复盘与后续安排。** 管理员查看运行结果、审核记录和有效真人反馈；系统独立计算任务状态与翻转，管理员据此安排后续挑战。操作身份和结果均留存，普通用户只能查看允许公开的进度。

本场景统一覆盖管理员的日常审核、挑战启动、过程管理、取消、失败处理和登记重试。

### 场景五：通过 MCP 查看统计并永久失去该题投票权

1. 用户通过自己的 token 调用 `list_tasks` 和默认 `get_task` 阅读公开内容，不影响投票资格。
2. 用户明确选择读取该题投票统计，客户端说明永久失去该题投票权的后果后提交显式统计请求。
3. 平台先按账号与任务保存永久资格变化，再返回统计；统计请求本身不提交选票。
4. 该账号之后在网站也不能再投这道题，换 token、换作品对或新增作品均不恢复；其他任务的资格不受影响。
5. 网站用户通过“跳过投票并查看统计”入口执行相同流程。

### 场景六：看板与热度榜同页查看

1. 用户在一个页面看到整体差距看板和热度排行榜；排行榜按热度降序排列已发布任务。
2. 用户可直接浏览平台 / 分类汇总、任务热度与摘要；首页推荐顺序由平台推荐规则决定。
3. 点击任务进入详情；从榜单或看板下钻到该题具体得票和胜率时，仍经过 US-36 的资格变更。

## 5. 对外 MCP 与内部业务能力

### 对外 MCP（内容只读）

| 工具与读取方式 | 返回内容 | 对用户投票资格的影响 |
| --- | --- | --- |
| `list_tasks` | 已发布任务列表，可按基础状态、分类和更新时间筛选；不附具体投票统计 | 无 |
| `get_task` 默认读取 | 已发布任务与作品、公开配置和评论、资格状态、公开运行摘要、网站入口 | 无 |
| `get_task` 显式查看投票统计 | 单题统计与永久不可投票状态；需事先明确后果 | 平台先永久关闭该账号的本题后续投票资格，再返回统计 |

“内容只读”表示 MCP 不发布内容、不投票、不控制云端运行；**显式读取投票统计会产生永久的资格变化**，不能将该调用描述为无副作用。普通读取和自动预取不触发此操作，客户端不能在未表达查看统计意图时自动代选。

若提供对应的用户 REST 查询，使用相同的统计门槛及账号记录，不开放绕过门槛的统计路径。具体请求字段后续定义，工具范围仍为 `list_tasks` 与 `get_task`。

### 云端内部交互职责

以下是业务交接，不预设协议、接口路径或云端实现方式。运行控制只由官方后台承担。

| 职责 | 发起方 → 接收方 | 输入 → 输出 | 关联故事 |
| --- | --- | --- | --- |
| 创建运行 | 平台管理员 Dashboard → 运行管理 | 已发布任务、配置、预算 → 运行标识或拒绝原因 | US-30 |
| 准备材料 | 运行管理 → 任务 / 审核状态 / 授权 / 学习材料 | 运行目标、角色 → 各角色允许接收的材料版本 | US-15、US-20 |
| 学习经验 | 云端学习步骤 → 经验库 | 可用作品与反馈 → 经验 / 标准新版本 | US-16、US-17 |
| 验证投票者 | 验证模块 ↔ 投票者 | 隐藏答案的作品对 → 预测 → 独立准确率与资格 | US-18 |
| 生成候选 | 运行管理 ↔ 生成者 | 任务、经验、有限反馈 → 候选与实际配置 | US-32 |
| 匿名评判 | 评测模块 ↔ 投票者 | 匿名作品对 → 选择、理由 → 可传递反馈 | US-33 |
| 推进与停止 | 运行管理 / 官方后台 → 后续步骤 | 当前结果、额度或官方指令 → 改进、结束或失败原因 | US-19、US-31、US-34 |
| 登记并送审 | 云端运行 → 作品 / 审核模块 | 最终候选、配置、运行关联 → 待审作品或拒绝原因 | US-05、US-27 |
| 审核发布 | 平台管理员 Dashboard → 发布模块 | 待审作品与审核结果 → 公开参选或驳回 | US-27 |
| 记录过程 | 各步骤 → 运行记录 | 阶段结果、用量、关联 → 受权限控制的记录 | US-21、US-35 |
| 真人复验回流 | 真人投票 → 材料 / 状态 | 有效且具备投票资格的人类判断 → 反馈样本、任务状态、可能的翻转 | US-22、US-10、US-36 |

原外部 `submit_entry`、`get_learning_material`、`submit_predictions`、`report_loop` 的业务职责由作品登记、材料准备、独立验证和内部记录承接，均不作为当前用户 MCP 工具开放。

## 6. 版本范围与验收重点

### MVP（黑客松）

- 页面：平台推荐的无限发现首页；看板简版与热度排行榜合并页面；任务详情及真人投票；独立的管理员 Dashboard 用于日常审核和云端挑战管理。
- 投稿：常见文件格式、压缩包、链接；新任务必须同时提交双方作品；所有用户可向任何公开可见任务单方追加作品，上传时填写授权和配置，原任务不重新送审。
- 发布：草稿、待审核、驳回、已发布、下架等状态；任务、追加作品与云端作品全部经过发布审核。
- 参与：账号、匿名真人投票、评论；用户及 MCP 可直接查看统计，代价是永久放弃该题之后的投票权。
- MCP：内容只读 `list_tasks` 与 `get_task`，默认无具体投票统计；显式统计读取与网站共用永久资格记录。
- 云端：官方后台独占启动、取消、重跑与配置权限；按状态准备材料、生成 / 评判、独立验证、匿名对抗、预算上限、最终作品送审。
- 运行与学习：过程记录、失败反馈、必要去重、配置与实际模型记录、角色隔离、经验版本及真人反馈样本。
- 比赛模型：至少一个核心生成 / 评判步骤真实使用符合要求的 NVIDIA 开源模型及 Nebius 服务，能够追溯其结果。

核心运行记录、最终作品关联、发布审核和永久投票资格检查均属于 MVP，不能推迟到后续才补上。

### V1

- 在同一个看板排行页面增强分类 / 时间趋势、翻转详情与运行关联。
- 由官方后台配置按额度和策略进行的自动学习、再挑战及跨任务经验复用。
- 增强视频在线预览、播放与对应云端处理；常见视频文件上传已纳入 MVP。
- 推荐与热度计算优化，以及限流、审核工具、运营分析与查询文档完善。
- 用户 MCP 不新增投票、发评论、投稿或云端控制能力。

### 关键验收场景

| 场景 | 应观察到的结果 |
| --- | --- |
| 打开首页并持续下滑 | 平台推荐的任务持续加载，有去重、加载和结束反馈，不自动读取投票统计 |
| 查看整体差距与热门任务 | 同页展示看板和排行榜，排行榜按热度排序 |
| 新任务只提交人类或 agent 一方 | 可暂存草稿，不能提交发布审核；必须补齐双方 |
| 非任务发布者向任意公开可见任务追加人类或 agent 作品 | 所有用户均可提交，无需任务作者批准；只处理新增作品，原任务保持已发布 |
| 已永久失去该题投票权的用户追加作品 | 仍允许投稿，投票资格不会因此恢复 |
| 平台管理员进入 Dashboard | 集中处理日常审核、举报、挑战启动与管理、异常和额度；普通用户不可执行管理操作 |
| 上传压缩包或提供链接 | 作为作品交付形式接收并进入审核，不绕过来源、授权或配置要求 |
| 任务或作品待审、驳回、下架 | 不出现在公开发现、榜单、MCP 内容、投票候选或云端学习材料中 |
| 用户通过网站或 MCP 查看具体投票统计 | 先记录该账号对该题永久不可投票，再返回统计 |
| 看统计后换 token、换作品对或任务新增作品 | 该账号仍不可投该题，其他任务资格不受影响 |
| 默认读取任务或预加载推荐卡片 | 不返回具体统计，不触发资格变化 |
| 查看统计与投票并发 | 按平台先后记录处理，资格关闭后不能新增票，已有有效票保留 |
| 普通用户尝试启动、取消、重跑或调整云端配置 | 用户网站、MCP 和内部调用均拒绝，只有官方后台可控制 |
| 官方选择已发布但领先结论待定的任务 | 可追加生成并送审，不获取偏好学习材料 |
| 人类作品未授权、未审核或材料不足 | 不读取受限参照，不伪造验证通过，官方后台得到明确原因 |
| 投票者验证未通过或配置变更 | 不凭旧成绩直接进入对抗 |
| 达到预算 / 轮数上限、模型出错或官方取消 | 有真实停止原因，迟到结果不继续推进 |
| 云端最终作品登记成功或发生重试 | 同一候选只有一份作品，先待审，通过后才进入真人投票 |
| 云端预测获胜或作品审核通过 | 不等于真人认可或任务翻转，最终结论仍由有效真人投票决定 |
| 参赛演示核对模型 | 能从作品或评测结果追溯实际 NVIDIA 模型及 Nebius 服务使用 |
